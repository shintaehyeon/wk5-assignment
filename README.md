# 작은 도서관

OSS 5주차 과제. HTML, CSS, JavaScript로 만든 도서관리 페이지입니다.
`index.html`을 브라우저에서 열면 실행됩니다.

## 파일 구성

- `index.html`: 홈
- `js_dynamic.html`: 읽고 싶은 책 추가, 입력 초기화, 항목 삭제
- `crud.html`: 도서 등록, 목록 조회, 수정, 삭제
- `style.css`: 공통 스타일

## 주요 기능

도서명, 저자, 분류, 출판사, 가격을 입력해 도서를 등록합니다.
목록에서 수정 버튼을 누르면 기존 정보가 입력창에 표시됩니다.
수정 취소를 누르면 기존 정보가 유지되고, 삭제는 확인창에서 확인한 경우에만 처리됩니다.

추가와 수정에는 같은 입력 검사를 적용합니다.

- 모든 항목 필수 입력
- 도서명 2~100자
- 저자와 출판사 각각 50자 이하
- 목록에 있는 분류 선택
- 가격 0~1,000,000원의 정수

도서 정보는 `books` 배열에 저장합니다. `editingId`로 수정 중인 도서를 구분하고,
`nextId`를 증가시켜 삭제한 도서의 ID를 다시 사용하지 않습니다.
입력값은 `textContent`로 화면에 표시합니다.

새로고침하면 변경 내용이 사라지고 초기 도서 3권으로 돌아갑니다.

ChatGPT/Codex의 도움을 받아 초기 코드 작성, 코드 정리, 입력 검사와 DOM 처리 점검을 진행했습니다.

- 내가 직접 수정한 부분: 도서 추가·수정·삭제를 시도하면서 동작하지 않는 부분을 질문했고, AI의 도움을 받아 관련 코드를 점검하고 정리했다. 길게 붙어 있던 HTML과 CSS는 줄바꿈과 들여쓰기를 정리하고, 불필요한 주석과 안내 문구를 줄였다.
- Problem & Solution: 도서를 추가하거나 수정·삭제할 때 기대한 대로 동작하지 않는 문제가 있었다. 해결을 위해 입력값 검사, 수정할 도서를 ID로 찾는 과정, 삭제 확인창 처리, 배열 변경 후 목록을 다시 출력하는 흐름을 점검했다. 현재 코드에는 이 처리들이 반영되어 있지만, 당시 문제의 정확한 원인은 확정하지 못했다.
- Reflection: 이번 작업에서 중요했던 부분은 도서 정보를 담은 배열과 화면에 보이는 목록을 함께 관리하는 것이었다. 추가·수정·삭제로 배열이 바뀐 뒤에는 목록을 다시 출력해야 하고, 수정할 때는 어떤 도서를 선택했는지 ID로 구분해야 한다. 아직 이벤트가 실행되는 순서와 수정 모드가 초기화되는 과정은 코드를 보면서 더 익힐 필요가 있다.
